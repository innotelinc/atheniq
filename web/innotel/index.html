Cerulean

Certificate and DNS management through one API: zone records, certificate issuance, and proxy-host provisioning. Cerulean is how our own domains — and our partners’ — get from a zone file to a working TLS endpoint without a ticket, and it is the identity and trust layer the rest of the family signs in against.

cerulean.innotel.us →

Sage

A course-taking agent that sits in the lecture rather than beside it: it listens to the room, watches the screen, the board or a mirrored phone, reads the material it was given, and answers quizzes, tests and essays in the learner’s own register — with the working and the confidence that earn the mark. Three layers shape every reply: a formed student voice, your settings, and memory it wrote itself between classes. Self-hosted on plain Node with no dependencies, installable to a phone, and driven by our own gateway. iOS still will not let a web page capture another app, so screen mirroring and the relay are written down rather than pretended away.

sage.innotel.tech → Live

ONYX

Our storage and edge platform: S3-compatible buckets, signed access, NFS shares and the operational tooling that keeps public hosts reachable and private ones private. It is where the estate's documents, exports and media actually live.

Cantus

A realtime voice standard built around one socket: no SIP, no SDP, no RTP and no port range to open, and a call that either connects or says why it did not. Published as a specification with a dependency-free Perl reference stack — NAT traversal always on, one round trip to negotiate, and every path decision an event you can assert or log.

innotelinc.github.io/cantus →

Warden browser

A privacy-first desktop browser and operator console for people who audit networks: ad and tracker filtering enforced in code, no cookie jar unless you ask for one, DNS over HTTPS, and a real shell, mail, unified messaging and Scry — which takes a live site apart and hands back a rebuildable project — docked beside the page you are reading. Windows x64, open source.

innotelinc.github.io/warden →

Warden mobile

The same private surfaces in a Capacitor shell: WARDEN's Android and iOS builds, with the browser, messaging and console panes the desktop app carries, installed from the signed release artifacts rather than a store.

github.com/innotelinc/warden — releases →

SCIF Privacy

Messaging where the server never holds a readable message: keys are made and each message sealed on the device (ECDH P-256, HKDF-SHA-256, AES-256-GCM), and the API stores only ciphertext, public keys and account metadata — losing the passphrase means losing the history, with no server-side recovery. Written down as it is: an early, unaudited prototype whose README lists exactly what it does not do.

github.com/innotelinc/scif → Prototype

Distro

Tenancy for AI app building: accounts, one gateway key per person, a quota and a spend cap on every account, a credits ledger, usage and fourteen-day spend rollups, and the operator console an admin works in. Distro is the layer every model turn in Genie passes through.

admin.distro.innotel.us →

Genie

How we work

Small team. Real systems. No theatre.

We are builders first. That means we run what we ship, we measure what we claim, and we prefer a boring, inspectable system to a clever one nobody can operate at 3am.

“Put the intelligence in the product, not in the pitch. Then prove it with a learner who finishes, a course that publishes and a service that stays up.”

01

Ship the whole thing

Product, platform and curriculum are one system. A course is not done until it is enrolled, assessed and credentialed.

02

Measure the model

Every AI feature has an evaluation, a fallback and a cost ceiling. We do not ship a demo and call it a product.

03

Own the operations

We run the edge, the database and the pager. The same team that designs the service is the team that answers for it.

04

Leave it legible

Documented interfaces, reproducible deploys, and no dependency we cannot replace. Our clients inherit systems, not mysteries.
