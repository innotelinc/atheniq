Inputs, Steps, Checks, Escalation

A workflow that works in a demo and fails on a Tuesday is missing one of four things: a clear input, a defined output, a human check, or a path for the case the tool cannot handle. Build all four before the pilot.

1. The input contract

State what the workflow expects: which fields, which format, which source system, and what happens when a field is missing. "Whatever the user pastes" is not a contract; it is a way to send restricted data somewhere it should not go.

2. The step

One job per step. If the assistant is asked to classify, draft, and decide, a failure in one contaminates the others. Keep the model's task narrow enough that a reviewer can describe what it did.

3. The output format

Define the shape before the content: the fields, the order, the length, and the required labels. A structured output is checkable; a paragraph is not. Where the output feeds another system, validate the format rather than trusting it.

4. The human check

Name the person and the specific check: "the agent verifies the account balance and the refund policy before sending". A check without a name and a criterion is a hope.

5. The escalation path

Low confidence, missing data, an angry customer, a value above a threshold, a policy exception — each needs a route to a person. The route must be visible in the interface, not buried in a document.

FailureWhat should catch it

Testing the failure modes is the difference between a pilot and a demo.

Try this

Take the step you chose in chapter 1 and write the five parts. Then deliberately break it three ways and record which control caught each break. Any break that reached the output is a missing control.
