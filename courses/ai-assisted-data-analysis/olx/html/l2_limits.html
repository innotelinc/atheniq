Prediction, Explanation, Cause

A model that predicts well is not a model that explains, and neither is a model that proves cause. Confusing the three is the most expensive mistake in applied analytics, because each supports a different sentence and only one of them survives scrutiny.

Three different claims

ClaimWhat it needsWhat it does not tell you
"This account is likely to leave"A model that ranks riskWhy, or what would stop it
"Low usage is associated with leaving"Observed correlationWhether usage causes leaving
"Increasing usage reduces leaving"An experiment or strong causal designWhether the effect holds for every segment

Base rates

If 2% of accounts leave each month, a model that says "nobody leaves" is 98% accurate and completely useless. Accuracy alone hides this; precision on the group you act on does not. Always ask: what is the base rate, and what does the model add over it?

Where a model is accurate and still unhelpful

A churn model can rank the whole customer base well and still be weak for the small, high-value segment the team actually cares about. Aggregate metrics hide segment performance. Check the group you will act on, not the population average.

Reading a confusion matrix

  • True positives: the accounts flagged that did leave — the ones the intervention can reach.
  • False positives: flagged, did not leave — wasted effort, and a cost the business case must include.
  • False negatives: not flagged, did leave — the miss that determines whether the model is worth using at all.

The right balance depends on the cost of each cell, not on the model's headline score.
