Check Before You Send

Verification is a routine, not a personality trait. People who catch AI errors reliably are not more suspicious; they follow the same four steps every time, and they do it while the draft is still cheap to change.

The four steps

  1. Name the claims. Split the draft into things that can be true or false: numbers, names, dates, policies, quotations, causal statements.
  2. Find the source. For each claim, name the document or system that would settle it. If no source exists, the claim does not ship.
  3. Compare. Open the source and read the specific line. "It sounds right" is not a comparison.
  4. Record the decision. Note what you checked and what you changed. This is what lets a colleague trust the work without repeating it.

Check the expensive things first

You do not need to verify every adjective. Rank by what a wrong claim would cost: a commitment to a customer, a number that drives a decision, a policy that determines eligibility, a safety instruction. Those get checked first and in full. Style gets a read.

The pressure problem

The check is most likely to be skipped when the draft looks good and the deadline is close. That is exactly when an error travels furthest. A useful sentence for that moment: "I can send it in ten minutes once I have checked the two figures — or I can send it now and mark the figures as unverified." It offers a choice without pretending the check is optional.

What good looks like

  • The draft and the source are open side by side.
  • Every number has been recomputed or read from the owning system.
  • Every policy statement has a named document behind it.
  • Anything unverified is labelled as such, or removed.
  • Someone's name is on the send — a person, not "the AI".

Try this

Take an AI draft you have actually sent. Run the four steps on it now and count the claims. Then write the one rule you will keep for the next draft — most learners choose something narrow and concrete, like "no number goes out that I have not opened the source for".
