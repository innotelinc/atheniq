Data Literacy & Spreadsheets

Data literacy is the ability to read a table, ask a sensible question of it, and say clearly what the answer does and does not support. Almost every operations role now assumes it, and almost all of it happens in a spreadsheet before it happens anywhere else.

The vocabulary

  • Row — one observation: one ticket, one sale, one learner.
  • Column — one variable measured the same way for every row.
  • Categorical — a label from a fixed set (region, status).
  • Numeric — a quantity you can add up (minutes, revenue).
  • Ordinal — an ordered label (low / medium / high, a survey scale). Order matters; the gaps may not.

Tidy data

One table, one row per observation, one column per variable — no totals rows in the middle of the data, no merged header cells, no colour used to carry meaning. A tidy table is what every later step (filter, pivot, chart, SQL) assumes.

Merged cells / two header rowsFilters and pivots break or silently skip

Numbers stored as textMaths and sorting go wrong, quietly

Spreadsheet essentials worth knowing cold

  • Relative vs absolute references — A1 moves when you fill; $A$1 does not.
  • Named ranges — a formula you can read six months later.
  • Structured tables — ranges that grow with the data instead of breaking at row 501.
  • Filters and sorts — reversible views, not edits: filtering to show a subset is safe, deleting the rest is not.
  • Keyboard discipline — a huge share of spreadsheet errors are paste-over-data and drag-fill accidents.

Before you analyse anything, read the first twenty rows and the last twenty. Most mistakes are visible there.
