Relational Thinking

SQL is the standard language for asking questions of a relational database — data organised as tables with rows and named, typed columns, related to one another by keys.

The relational model

  • Table — one entity type: customers, orders, learners.
  • Row — one instance of that entity.
  • Column — one attribute, with one data type.
  • Primary key — the column (or columns) that uniquely identify a row.
  • Foreign key — a column that references another table's primary key, expressing the relationship.

Why normalise at all

Storing each fact once removes the three anomalies: an insert that cannot be made without inventing unrelated data, an update that has to be repeated in many places, and a delete that loses information you meant to keep. Normalisation trades a little complexity in querying for consistency in storage.

Constraints are your friend

NOT NULL, UNIQUE, CHECK, primary and foreign keys, and the data types themselves are the database enforcing your rules. A rule expressed as a constraint cannot be forgotten by the next application that writes to the table.

Read a schema before you query it: which column is the key, which are nullable, what the types are, and how the tables connect. That is most of writing correct SQL.
