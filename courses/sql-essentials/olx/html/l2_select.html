Querying with SELECT

SELECT reads. Everything else — filtering, sorting, limiting — narrows or orders what it returns.

The shape of a query

ClauseWhat it does
SELECTWhich columns (or expressions) to return
FROMWhich table (or join) to read
WHEREWhich rows to keep
GROUP BYCollapse rows into groups
HAVINGFilter the groups
ORDER BYSort the result
LIMITReturn only the first N rows

Written order is not execution order. The engine reads FROM, filters with WHERE, groups, filters groups with HAVING, projects the SELECT, then sorts and limits — which is why a WHERE clause cannot use a SELECT alias.

Filtering

  • WHERE status = 'open' AND priority IN ('high', 'urgent')
  • BETWEEN is inclusive on both ends.
  • LIKE matches patterns: '%beta%' anywhere, 'beta%' at the start.
  • Compare against NULL only with IS NULL / IS NOT NULL — = NULL is never true, because NULL means "unknown", not "empty".

Expressions and aliases

Compute in the query and name the result: SELECT price * quantity AS line_total. Aliases make output readable and let an outer query reference the value. Be explicit about rounding and units so the number means something.

Select the columns you need rather than SELECT *: it is clearer, it survives a column being added, and it does not drag large unused data across the network.
